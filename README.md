# Resumind — AI Resume Analyzer

Resumind helps job seekers review a resume against a target role. Upload a text-based PDF, optionally add the company, job title, and job description, and get an AI-generated score with actionable feedback on ATS suitability, tone and style, content, structure, and skills.

The app is built with React Router and uses Puter.js in the browser for sign-in, AI requests, file storage, and key-value storage.

![Resumind application preview](./public/readme/hero.webp)

## Features

- Sign in with Puter.
- Upload or drag and drop a PDF resume (up to 20 MB).
- Add optional job details to tailor the review.
- Extract readable text from the PDF and generate a preview of its first page.
- Receive an overall score and category-level feedback with positive observations and suggested improvements.
- View previous analyses and reopen the saved PDF and preview.
- Analyze the same resume for different roles by creating separate submissions.

## How it works

1. Sign in, then open **Upload Resume**.
2. Select a PDF and optionally enter the company name, job title, and job description.
3. Resumind extracts text from the PDF in your browser and creates an image preview of page one.
4. The resume text and review instructions are sent to the configured AI model through Puter.js.
5. The PDF, preview, and structured feedback are stored using Puter file storage and key-value storage.
6. The result page displays the resume preview, overall score, ATS tips, and detailed category feedback.

Feedback covers:

| Category | What the review considers |
| --- | --- |
| ATS | Suitability for applicant tracking systems |
| Tone & Style | Wording, professionalism, clarity, and consistency |
| Content | Evidence, impact, and completeness of resume content |
| Structure | Organization and readability |
| Skills | Relevant skills and how they are presented |

Scores are generated by an AI model and are intended as guidance, not a hiring decision or a guarantee of ATS performance.

## Requirements

- Node.js 20 or later
- npm (the repository includes `package-lock.json`)
- A browser with JavaScript enabled
- A Puter account and access to Puter.js authentication, AI, file storage, and key-value storage

No application-specific `.env` file is required by the current code. Puter.js is loaded in the browser from `https://js.puter.com/v2/`.

## Getting started

### Clone the repository

Make sure Git and Node.js 20 or later are installed, then clone the repository and move into the project directory:

```bash
git clone https://github.com/1141-raf/ai-resume-analyzer.git
cd ai-resume-analyzer
```

### Install dependencies and run locally

```bash
npm ci
npm run dev
```

Open the local URL printed by Vite. Sign in through Puter before uploading a resume. The development server supports hot reloading.

## Production build

Build the application and start the React Router production server:

```bash
npm run build
npm run start
```

The build output is written to `build/`. The `start` script serves `build/server/index.js`; configure your hosting platform to run `npm run start` and expose the port expected by that platform.

## Docker

The included multi-stage Dockerfile installs dependencies, builds the app, and runs the production server in a Node 20 Alpine image:

```bash
docker build -t resumind .
docker run --rm -p 3000:3000 -e PORT=3000 resumind
```

If your hosting platform assigns a different port, set `PORT` to that value and map it accordingly. The app still requires a browser connection to Puter.js services; Docker does not provide a separate AI or storage backend.

## Data, privacy, and cleanup

- PDF text is extracted in the browser and included in a request to Puter.js AI. Resume content may contain sensitive personal information; review Puter's applicable privacy and data-handling terms before using the service.
- The original PDF, a first-page preview, and the analysis record are saved through Puter file and key-value storage associated with the signed-in user. This application does not currently use its own database.
- On an analysis failure after file upload, the app attempts to delete the uploaded PDF and preview. Verify your Puter storage if a request is interrupted unexpectedly.
- The `/wipe` route is destructive: it deletes files found in the Puter file-storage root and flushes the app's key-value storage. Do not use it unless you intend to remove that stored data.
- Resumes must contain extractable text. Scanned/image-only PDFs are not supported by the current text extraction flow. If a PDF has fewer than 80 extracted characters, analysis is rejected.

## Troubleshooting

**Puter.js failed to load**

- Check your internet connection and confirm the browser can access `https://js.puter.com/v2/`.
- Check browser extensions or network policies that might block third-party scripts.
- Reload the page after the script is available.

**Sign-in or storage actions fail**

- Confirm you are signed in through Puter.
- Check that the browser allows the Puter services used by the app and that your account can access them.

**The PDF cannot be analyzed**

- Confirm it is a PDF smaller than 20 MB.
- Use a text-based PDF exported from a document editor; scanned pages may not contain extractable text.
- Try again if the AI request times out. Analysis requests are aborted after two minutes.

**The build or type check fails**

- Use Node.js 20 or later.
- Reinstall dependencies with `npm ci`, then run `npm run typecheck` or `npm run build` to see the relevant diagnostics.

## Development notes

- React Router 7 is configured for server-side rendering.
- Vite integrates Tailwind CSS 4 and TypeScript path aliases (`~/*` maps to `app/*`).
- PDF processing uses `pdfjs-dist`; the worker is served from `/pdf.worker.min.mjs`.
- The AI response is requested in a strict JSON schema and validated before the result is saved.
